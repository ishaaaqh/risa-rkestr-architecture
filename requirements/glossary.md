# Rkestr Domain Glossary

| Term | Definition |
|---|---|
| User | Canonical application identity |
| Workspace | User-facing tenant/security boundary |
| Membership | Relationship between User and Workspace |
| Role | Workspace-scoped collection of permissions |
| Permission | Atomic authorization capability |
| Work Item | Core unit of work |
| Owner | User responsible for the Work Item |
| Assignee | User who executes the Work Item |
| Created By | User who created the Work Item |
| Subtask | Meaningful unit of work under one Work Item |
| Work Session | Focused execution period |
| Dependency | Logical prerequisite relationship between Work Items |
| Blocker | Active condition preventing progress |
| Context | Broad environment such as PERSONAL, FAMILY, WORK |
| Category | Fine-grained classification |
| Priority | Relative attention preference |
| Importance | Consequence/value classification |
| Urgency | Time-sensitivity classification |
| Task Nature | Execution style: IMMEDIATE or EFFORT_BASED |
| Soft Deadline | Preferred target |
| Hard Deadline | Meaningful external/business constraint |
| Reminder Plan | Rules describing when reminders should occur |
| Reminder Instance | Concrete scheduled reminder |
| Notification | Delivery mechanism for a reminder/event |
| Audit Event | Append-only record of a significant action |
| Outbox Event | Transactionally persisted event awaiting publication |
