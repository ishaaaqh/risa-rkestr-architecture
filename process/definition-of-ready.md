# Definition of Ready

A ticket is Ready for implementation when:

- Business intent is clear.
- Scope and non-goals are stated.
- Relevant architecture decision is known.
- Dependencies are identified.
- API/data/event changes are identified where applicable.
- Acceptance criteria are testable.
- Security and authorization impact is considered.
- Observability/audit impact is considered for consequential behavior.
- Required ADR is created or linked when architecture changes.
- Cross-repository implementation tickets are linked when applicable.

A ticket that changes an approved architectural decision is not Ready until the architecture change is reviewed and documented.
